Hidden Risks of Vibe Coding

Your AI-built lending app scans an ISBN and marks the book as on loan. A reader brings a second copy to the desk. Can they borrow it?

A prompt like “mark this book as borrowed” leaves the AI to choose what “book” means. An ISBN identifies the edition. A loan belongs to one physical copy. With OnToGraPh, the person who knows the lending policy can define that distinction, and the developer can test it against the draft model.

Four questions to ask before you rely on the data

Suppose Finance and the project office both export a field called WBS. Both files contain 0017. Before joining the records, agree on the answers.

Dictionary

What does this field mean here?

Keep 0017 as text so a file import preserves its leading zeros. Record who defines it in each department.

Taxonomy

Which group does this record belong to?

Classify a Finance posting object and a PMO work package separately. Give an unclassified record a review path.

Ontology

What does this identifier refer to?

Link each department’s code to the business object it identifies. A shared spelling alone cannot establish that two records describe the same object.

Data stewardship

How would we know a change took effect?

Keep the source, owner and effective version. Ask the receiving team to check its own output after a release or withdrawal.

What does WBS 0017 mean here?

Finance, source available. The Finance definition identifies 0017 as a posting object. In the project office the same code identifies a work package. A bare code leaves the choice unresolved.

The workbook acknowledged the rule. What did it count?

In the recorded WBS pilot, the project workbook acknowledged the department-qualified rule while its eligible budget still showed €2,000. Once it applied the rule, that same workbook showed €800. After withdrawal, the first check still found €800. When the workbook went offline, the team could no longer verify its state. A fresh reading of €0 after recovery confirmed withdrawal for the test records.
