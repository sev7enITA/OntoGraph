# 氛围编程的隐性风险

书架上的两本书可以共用同一个 ISBN。如果借阅应用用 ISBN 记录可借状态，借出第一本时，第二本也可能显示为已借出。个人图书馆示例将版本、每一本实体书和借阅记录分别建模。[打开个人图书馆场景](https://openontograph.org/zh/journey/personal-library/)

## 面向智能体的本体（Agent-ready ontology）

“请将这笔费用记到 WBS 0017。”在财务部门，这个编码指记账对象；在项目管理办公室，它指工作包。影片中，智能体核对这两种含义，先问“你指的是哪个部门？”，并暂缓入账。这段示例对话展示了智能体如何使用模型。启用记账操作前，请在接收应用中测试缺少部门的情况。[从 0:45 观看示例](https://openontograph.org/zh/launch/#agent-ready) · [探索 WBS 场景](https://openontograph.org/zh/journey/department-wbs/)

## 可选集成路径

四个引导场景、自定义应用流程和在线 Studio 都支持独立使用。展开“可选集成”，可在新标签页查看已记录的分支。PolicyWatcher 可提供只读政策变更证据；PALO 可接收案例并交由人工复核。打开这些链接会保留草稿，不会向这两个框架发送草稿内容。[来源证据接收](https://openontograph.org/pilot/zh/#policywatcher) · [人工复核交接](https://openontograph.org/pilot/zh/#palo) · [从隐性风险到可验证的决策](https://openontograph.org/zh/launch/)


## 描述自己的应用

从[首页预览](https://openontograph.org/zh/#hidden-risks)播放图书馆或 WBS 示例，也可以直接打开[描述我的应用](https://openontograph.org/zh/hidden-risks/#my-case)。用 10 至 3,000 个字符说明参与者、对象和待做的决策。例如：应用将志愿者分配到避难所，单独追踪“夜班”。可以用引号标记需要保留的业务术语。

也可以直接写出定义和关系。例如：“夜班”是指午夜后开始的值班。“夜班”属于“班次”。“班次”依赖于“志愿者”。在提案中核对生成的词条、分类层级和依赖关系。

浏览器用双语规则提取候选术语。四个面板分别显示风险问题与建议测试、关联原描述用词的词条、拟议分类和带有类型的依赖关系。未识别的术语留待分类。首页图表中的数量来自当前选择的示例。

在同一标签页选择**在 Studio 中复核**。登录后，有编辑权限的用户会获得独立的私有草稿工作区。展开面板，修改定义、术语分类或关系，选择**应用提案修改**，再选择**保存草稿**。收藏工作区地址即可再次打开已保存的版本。只读用户可以查看提案。选择**下载草稿 JSON** 可获得离线使用的副本。

提案在浏览器中生成。在 Studio 中打开时，模型及原始描述会发送到已认证的服务。描述的初始证据状态为“不充分”。示例规则及两个探针用于测试人工复核条件。负责人仍需核实术语，并在实际使用数据的应用中检查业务决策。

## 从原型中选一个需要做判断的问题

例如：“我能把手里的这本书借出去吗？”先写下三个例子：一个应允许，一个应暂缓，一个缺少必要信息。熟悉借阅业务的人就能给出这三个例子，团队随后再选择数据库或 AI 模型。

| 要回答的问题 | 要记录的内容 | WBS 场景示例 |
| --- | --- | --- |
| 这个术语在这里指什么？ | 词条、定义和负责人 | 财务部门用 `0017` 表示记账对象，项目管理办公室用同一编码表示工作包。 |
| 这个定义适用于哪里？ | 分类和适用范围 | 分别记录财务和项目管理办公室的部门上下文。 |
| 哪项决策依赖它？ | 从字段到概念、控制规则或应用的关系及其类型 | 同一串字符既用于判断哪些记录可以入账，也用于判断哪些预算可以计入工作表。 |
| 这条记录能否用于这项决策？ | 数据检查、来源和复核方式 | 保留前导零，要求提供部门；编码缺少部门时，将映射交由人工复核。 |
| 应用实际做了什么？ | 使用方、模型版本、输入、预期和独立观测结果 | 重新计算工作表，将可计入的预算与该版本的预期值进行比较。 |

业务负责人说明例外情况和预期结果，开发者将差异写进模型并运行示例。双方再核对实际使用数据的应用。Studio 对已保存草稿的检查与应用中的实际观测分别记录。

## 用模拟数据试一遍

1. 在[交互示例](https://openontograph.org/zh/hidden-risks/#risk-lab)中切换部门和来源，观察只按编码匹配时哪些记录会被计入。
2. 打开[跨部门 WBS 场景](https://openontograph.org/zh/journey/department-wbs/)，在 Studio 草稿中查看相互矛盾的证据，并用场景清单验证决策。
3. 查看[双应用试点记录](https://openontograph.org/wbs/zh/)。Calc 已确认收到新规则，工作表却仍计入了 2,000 欧元预算。使用正确的工作表重新计算后，金额变为 800 欧元。规则撤回后，直到后续读数为 0 欧元，才验证工作表已停止计入这些记录。上述金额均来自本地试点的模拟数据。
