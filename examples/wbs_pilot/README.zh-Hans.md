# 一次 WBS 规则变更，两个独立应用

[English](README.md) · [实测结果](observed-summary.json) · [下载证据](observed-evidence.zip)

在财务部门，WBS 编码 `0017` 指一个过账对象。在项目管理办公室（PMO），同一编码指一个工作包。原规则接受已识别的编码。新规则还要求核实来源部门。Beancount/Beanquery 对原生会计账簿进行查询，计算符合条件的欧元金额。LibreOffice Calc 在独立的 OpenDocument 工作簿中重新计算预算。观察者分别读取这两个应用中三条测试记录的实际结果。

财务人员对本部门的映射给出置信度 0.85、影响程度 4/5。PMO 对缺少部门限定的编码提出异议，给出置信度 0.30、影响程度 5/5。即使两位指定审核人已投票，只要分歧未裁定，该候选版本仍然无法发布。新候选版本保留两条原始主张，并记录数据管理员选择了哪一条、理由、裁定时间及所依据证据的摘要。审核人对新候选版本重新投票。此处的数值是情景中的人工判断。

| 检查点 | 财务账簿符合条件的金额 | PMO 工作簿符合条件的预算 |
| --- | ---: | ---: |
| 初始规则 | 475 欧元 | 2,000 欧元 |
| 撤回初始规则 | 已核验为 0 | 已核验为 0 |
| 两方确认收到新版本 | 125 欧元，已核验 | 2,000 欧元，与预期不符。导入程序刻意重新打开旧模板。 |
| 安装正确的工作簿 | 125 欧元，已核验 | 800 欧元，已核验 |
| 两方确认收到撤回指令 | 已核验为 0 | 800 欧元，旧公式仍在生效。 |
| 工作簿暂时离线 | 保留上一次核验结果 | 未知，观察者无法读取。 |
| 恢复工作簿并实施撤回 | 已核验为 0 | 已核验为 0 |
| 重新审核并发布初始规则 | 475 欧元，已核验 | 2,000 欧元，已核验 |

两个金额代表不同业务指标。撤回核验要求三条具有正金额的源记录仍在，应用重新计算后符合条件的金额均为零。恢复初始规则需要经过一次新的发布。证据包包含 15 份观测记录、70 个链接的登记事件和 4 个候选版本。故障为主动移开工作簿文件，恢复后再次运行 Calc。

## 离线核验证据

在仓库根目录运行以下命令。验证只需要 Python 3.10 或更高版本和本项目源码。

```sh
python3 -m examples.wbs_pilot.evidence examples/wbs_pilot/observed-evidence.zip \
  --expected-tip fcca37d9398ddc451708e6d98f2843244c83259e3cff5cba1ee751e9ca6e9424
```

在 `summary.json` 中选择检查点，并在 `artifacts/` 下找到其 `artifact_sha256` 所指文件。文件列出了原始账簿、查询、工作簿或 CSV 的名称和摘要。将链尾摘要独立保管，有助于检测整个证据包被替换。

## 复现两个应用的运行

安装 LibreOffice Calc，并让 `soffice` 命令位于 PATH 或 macOS 标准应用路径。在仓库根目录创建 Python 3.12 虚拟环境并运行：

```sh
python3.12 -m venv /tmp/wbs-pilot-env
. /tmp/wbs-pilot-env/bin/activate
python -m pip install beancount==3.2.3 beanquery==0.2.0
python -m examples.wbs_pilot.run out/my-first-wbs-pilot
python -m examples.wbs_pilot.evidence out/my-first-wbs-evidence.zip --package out/my-first-wbs-pilot
```

每次运行请使用新的输出目录。登记库、应用输入和 Calc 配置相互隔离。两个程序在同一台电脑、同一个操作系统账户下执行。消费者、审核人、发布人、观察者等分别使用登记库中的不同身份；角色步骤由脚本驱动。使用的是合成数据，未进行实际财务过账。此试点展示三条记录在本地原生应用中的行为。客户环境还需要验证真实身份、观察者的独立性和人工审批。
